# Target screening log

Last updated: 2026-10-15

Rule: a candidate qualifies only when a specific in-scope, externally callable state-changing function has a source-supported authorization mismatch and a feasible pinned local reproduction path. “No mismatch identified” is a screening result, not a claim that the program is safe. Hard stop: 60 minutes per candidate.

- **Synthetix** — Checked because the Immunefi scope added `SynthetixDepositContract (Proxy)` on 2026-06-21; the verified implementation ABI exposes a concrete admin surface (`addCollateral`, `updateCollateralConfig`, `removeCollateral`, `setWatcherQuorum`, `setWithdrawalExpiryTimeout`, `setPriceFeed`, oracle setters, vault/slippage setters, role management, and pause controls). **Not qualified this pass:** no setter with a missing/ineffective guard was source-confirmed; the audit records a 2025-10 review, while the linked `Synthetixio/v4-deposit-contract` repository currently returns 404 through the available GitHub source path, so ABI evidence alone cannot prove modifier behavior. Stop rather than infer a bug from the new scope entry. Sources: [Immunefi scope](https://immunefi.com/bug-bounty/synthetix/scope/), [verified implementation](https://etherscan.io/address/0xff6611190b48Cc920EF3c5DCbD356bF2C20D731F), [Guardian audit](https://www.guardian.security/portfolio/synthetix/deposit-contract-2025-10-20/).

- **Berachain** — Checked for recent admin/upgrade-related contract changes; the repository has recent implementation/upgrade activity, including FeeCollector recovery functionality and Honey implementation updates. **Not qualified in the time-boxed pass:** no exact in-scope sibling setter with a source-confirmed authorization mismatch was established. Sources: [Immunefi program](https://immunefi.com/bug-bounty/berachain/information/), [contracts repository](https://github.com/berachain/contracts), [recent contract changes](https://github.com/berachain/contracts/commits/main/).

- **Threshold Network** — Checked for recent Solidity contract and operator-setup changes. **Not qualified in the time-boxed pass:** no specific setter/initializer/override with a demonstrated authorization mismatch was isolated, and the published scope is broad (51 assets) while the primary Solidity repository documents a Hardhat workflow rather than CYDRA’s usual Foundry path. Sources: [Immunefi scope](https://immunefi.com/bug-bounty/thresholdnetwork/scope/), [Solidity contracts repository](https://github.com/threshold-network/solidity-contracts).

- **Maple** — Checked because the Maple V2 core repository is active and Foundry-based. **Not qualified in the time-boxed pass:** the core repository is an integration harness over many contract submodules, and the bounty includes deployed instances/proxies and future implementations; no single controller with a source-confirmed guard mismatch was established within the time box. Sources: [Immunefi scope](https://immunefi.com/bug-bounty/maple/scope/), [Maple V2 core repository](https://github.com/maple-labs/maple-core-v2), [bounty scope notes](https://immunefi.com/bug-bounty/maple/resources/).

## Outcome

0 of these 4 candidates qualified for immediate campaign dispatch. This is **not** a security clearance for any target: it means the required source-backed authorization mismatch was not established within the screening limit. Do not dispatch CYDRA on an ABI-only lead or a program-level “recent activity” signal. Next filter refinement should prioritize targets where (1) the exact in-scope implementation source and pinned revision are immediately available, (2) a small controller has a visible set of sibling setters, and (3) a fresh diff identifies the specific authorization-sensitive change before spending the full screen budget.
